# Changelog

## [Unreleased]

- FIN-391: добавлены unit/API-регрессии для трёх несовместимых пар типа/даты аналитики: canonical date/INVALID_FORMAT переводится в HTTP400, неполная ошибка producer без reason остаётся HTTP500. Runtime и строгий decoder не меняются.

- FIN-372: CI и линтеры используют общий источник `fin-assist/go-ci` по неизменяемому SHA; локальные команды и тесты скриптов используют проверенный кэш. Обновление и откат синхронизируют pins и копию bootstrap в одном PR. Runtime и публичный API не меняются.

- FIN-364: contracts/gen/go v0.7.0 и точная OpenAPI-копия merged `928bac0` (FIN-363). POST /v1/auth/phone требует phone, pd_consent_accepted, pd_consent_version (1–64 Unicode-символа), age_confirmed; четыре значения передаются USER вместе с доверенным IP/ключом. False остаётся сервисной проверкой после ключа/лимитов; добавлены 403 CONSENT_REQUIRED и 422 CONSENT_OUTDATED. Register подтверждает исходную receipt-версию без повторного чтения текущего документа; provider/evidence остаются в USER. Retry/no-store, сроки ответа и отсутствие скрытого повтора Start сохранены; условия совместной выкладки — docs/config.md.

- FIN-368: неизвестная gRPC-причина актуальности получает `unverified` с готовым текстом и прежней метрикой; пустой changed_since зарезервирован для подтверждённого равенства. Публичные source/encoding сценарии остались API-only, отдельные integration проверяют mapper+gRPC и rest+HTTP/JWT/gRPC компоненты.

- FIN-368 / FIN-339: contracts/gen/go v0.6.0 и точная встроенная OpenAPI-копия merged `1c624f5`. Сопутствующая совместимость шести JSON-операций: все Content-Encoding проверяются до чтения/size/decode, недопустимое значение — 400 без чтения тела приложением, его drain и RPC; полный startup Validate включает исправленные примеры и defaults. Auth/idempotency, bodyless и upload политики сохраняются.

- FIN-368: BFF передаёт открытые коды `unverified` и `time_zone` в `changed_since` и готовые тексты «Актуальность данных этого ответа не подтверждена» / «Обновились настройки часового пояса» в истории, reconnect-snapshot и SSE source; сохранён fallback для неизвестных enum. Технические версии данных в REST не добавляются.

- FIN-359: BFF не повторяет transport-мутации после потери ответа применённого split/join; открытый kind разбирается по generated descriptor, неполные категории отклоняются. Добавлены регрессии потери ответа, malformed search/change/categories, точных diagnostic counters, metadata и невырожденного deadline guard.

- FIN-359: шесть REST-операций ленты/поиска, деталей/смены категории, справочника и «Не подписка» через bank-statement-data. Точные моменты и готовые поля сервисов, проверка фильтров, search10s/16 МиБ только для поиска, verified identity и безопасные повторы; unit и HTTP→gRPC integration/API.

- FIN-360: диагностика отличает nil-навигацию от присутствующего пустого ключа; допустимый локальный год0000 сохраняется по RFC3339, верхняя граница формата защищена. Граница отказа на непредставимом typed Timestamp блока документирована.

- FIN-360: валидируются календарные ключи и присутствующие optional Timestamp новой проекции; неправильная typed-оболочка даёт безопасный500 с точной ограниченной диагностикой, opaque Struct остаётся неизменным. Метрики ListPeriods проверены на всех трёх уровнях.

- FIN-360: обязательные моменты и диапазоны аналитики/периодов не превращаются в epoch/null при неполном ответе сервиса; точные ограниченные диагностические метрики, счётчики coverage и контрактный учёт пустых полей до отказа.

- FIN-360: защищённые GET аналитики и периодов через AnalyticsService; открытая проекция блоков/Struct, состояний, навигации и фильтров без финансовых вычислений. Новый обязательный ANALYTICS_GRPC_ADDR, unit и HTTP→gRPC integration/API, contract fallback валюты и текста блокировки с пятью предсозданными сериями метрики.

- FIN-361: PATCH сохраняет retryable=false без явной REST-гарантии повтора; неизвестная тема отклоняется до RPC при дрейфе схемы, соответствие enum и protobuf проверяет unit-тест. Улучшены отрицательный сценарий NOT_FOUND и диагностика metadata в фикстуре удаления.

- FIN-361: PATCH и DELETE `/v1/profile` через `user.ProfileService`: optional-настройки, обновлённый профиль и идемпотентное удаление с пустым 204; verified identity, общий unary-дедлайн и scoped retry advice. Добавлены unit и HTTP→gRPC integration/API-сценарии.

- FIN-342: регрессия отрицательного остатка MIME-бюджета проверяет почти полный первый заголовок, файл 300 000 байт и предварительно прочитанные байты второго заголовка 5 МиБ; защита проверена удалением условия в локальном mutation-прогоне.

- FIN-342: перед разбором заголовков возможной второй multipart-части включается оставшийся общий бюджет оболочки; крупный лишний заголовок ограничен до выделений MIME-парсера и отменяет RPC без финализации.

- FIN-342: явно переданное пустое имя файла сохраняется как пустая часть hash identity FIN-297; отсутствие параметра filename по-прежнему отклоняется до RPC.

- FIN-342: отрицательные transport-тесты формы считают синхронное начало вызова gRPC-клиента, а не запаздывающую запись предыдущего отменённого RPC на сервере. Запрет лишних RPC и проверка отсутствия фиксации сохранены.

- FIN-342: активные загрузки при остановке дренируются как обычные HTTP-запросы до SHUTDOWN_TIMEOUT; немедленная отмена остаётся только у SSE. Локальные upload429 учитываются существующим счётчиком streaming-отказов с ограниченной меткой маршрута.

- FIN-342: чанки файла объединяются до 256 КиБ; заявленное тело выше суммарного лимита отклоняется до RPC. Отдельные лимиты загрузок 16 на процесс и 2 на IP не расходуют бюджет SSE; локальный отказ POST не разрешает повтор ключа.

- FIN-342: неизвестный UnreadReason сохраняет всю строку и готовый reason_name с транспортным reason=unknown и ограниченной метрикой, а не с молчаливой потерей записи. Известные коды и reason_name сохраняются без изменений.

- FIN-342: шесть защищённых REST/SSE-маршрутов импорта через StatementsService; потоковая multipart-загрузка с точным именем файла, отдельными бюджетами файла/оболочки и проверкой формы до gRPC EOF. Общий Status результата, безопасные тексты и scoped retry advice; новый обязательный STATEMENTS_GRPC_ADDR. Операции и аналитика не добавлены.

### Добавлено

- FIN-268 (FIN-331): публичный REST/SSE-API входа по телефону, регистрации, токенов, выхода, документов согласий, профиля и согласия помощника, сообщений, ответа и лимита помощника — 14 операций `openapi.yaml`. Проверки в порядке контракта (MAINTENANCE → версия клиента → токен → размер и схема тела → сервис), проверка JWT через go-identity v0.2.0, разрешённый список metadata в gRPC, перевод ошибок через `finerr.ToREST`, неизвестная ошибка — 500. SSE с heartbeat, собственными сроками и пределами потоков, завершение потоков при shutdown. Адрес клиента за доверенными прокси (`TRUSTED_PROXIES`) — из `X-Forwarded-For`. Новые настройки — `docs/config.md`.
- FIN-225 (часть, FIN-331): единый каталог `user_message`/`severity` ошибок BFF, включая тексты ошибок ответа помощника; REST `retryable` и вложенный `google.rpc.Status` ждут тега `gen/go` с FIN-224.
- FIN-290 (FIN-331): `make test-names` проверяет и `Fuzz…`, отклоняет `Example…`; collectors выбирают Fuzz-цели своего уровня.
- FIN-261: Go-каркас stateless HTTP BFF из go-service-template: два изолированных listeners, конфигурация, логи, health/readiness/метрики, ограниченный shutdown, Docker/systemd и три уровня автотестов. Бизнес-REST/SSE остаются в отдельных задачах.

- FIN-148: CI сохраняет stage-бинарь из проверенного образа с SHA, manifest и контрольной суммой.
