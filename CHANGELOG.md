# Changelog

## [Unreleased]

- FIN-342: шесть защищённых REST/SSE-маршрутов импорта через StatementsService; потоковая multipart-загрузка с точным именем файла, отдельными бюджетами файла/оболочки и проверкой формы до gRPC EOF. Общий Status результата, безопасные тексты и scoped retry advice; новый обязательный STATEMENTS_GRPC_ADDR. Операции и аналитика не добавлены.

### Добавлено

- FIN-342 (остаток FIN-225): contracts/gen/go v0.5.0, REST `error.retryable` по разрешению сервиса и безопасности всего исходного запроса; канонические вложенные `google.rpc.Status` в терминальных ошибках и failed-истории помощника с безопасным каталогом BFF и сохранением отдельного разрешения новой попытки. Совместимость и порядок выкладки/отката описаны в документации.
- FIN-268 (FIN-331): публичный REST/SSE-API входа по телефону, регистрации, токенов, выхода, документов согласий, профиля и согласия помощника, сообщений, ответа и лимита помощника — 14 операций `openapi.yaml`. Проверки в порядке контракта (MAINTENANCE → версия клиента → токен → размер и схема тела → сервис), проверка JWT через go-identity v0.2.0, разрешённый список metadata в gRPC, перевод ошибок через `finerr.ToREST`, неизвестная ошибка — 500. SSE с heartbeat, собственными сроками и пределами потоков, завершение потоков при shutdown. Адрес клиента за доверенными прокси (`TRUSTED_PROXIES`) — из `X-Forwarded-For`. Новые настройки — `docs/config.md`.
- FIN-225 (часть, FIN-331): единый каталог `user_message`/`severity` ошибок BFF, включая тексты ошибок ответа помощника; REST `retryable` и вложенный `google.rpc.Status` ждут тега `gen/go` с FIN-224.
- FIN-290 (FIN-331): `make test-names` проверяет и `Fuzz…`, отклоняет `Example…`; collectors выбирают Fuzz-цели своего уровня.
- FIN-261: Go-каркас stateless HTTP BFF из go-service-template: два изолированных listeners, конфигурация, логи, health/readiness/метрики, ограниченный shutdown, Docker/systemd и три уровня автотестов. Бизнес-REST/SSE остаются в отдельных задачах.

### Исправлено

- FIN-286: пример systemd-юнита для стенда привязывает публичный и operational listeners к `127.0.0.1`: метрики и HTTP без TLS не публикуются на внешних интерфейсах VPS; юнит дополнительно разрешает только loopback-трафик (`IPAddressAllow=localhost`, `IPAddressDeny=any`), env-файл стенда адреса listeners не задаёт.
- FIN-261: workflow ревью Claude проверяет происхождение PR отдельным read-only job и не выдаёт права записи PR из форков; ошибку API и удалённый head обрабатывает как отказ.
